# 检测效果实测

测的是 `Agent-Zero/build/BlueWhiteAgent.exe`（1.42 MB）。构建工具链 MinGW-w64 g++ 16.2.0，编译参数 `-std=c++20 -O2 -static -s`。跑法是 `BlueWhiteAgent.exe run <技能> <目标>`，全程不接大模型，只看确定性技能链路能拿到什么。靶场在 `靶机服务器/`，走本机回环 `http://127.0.0.1:8899`；PHP 8.5.11 已就位，靶场自检 137 项全过。

## 一、结论

| 指标 | 实测值 |
| --- | --- |
| 靶场考点可复现性 | 137 / 137 |
| 召回率 | 34.8%（23 / 66） |
| 准确率 | 82.3%（28 / 34） |
| 误报率 | 17.6%（6 / 34） |
| 越权拦截（L0 禁区） | 通过，0 条结论，审计 `allowed=false` |

统计口径是两个技能顺序跑进同一个数据目录再合并。6 条误报里，4 条其实站得住：页面注释确实写了接口路径，`Permissions-Policy` 确实没配，README 里也确实有内网地址——只是靶场真值表没把这几项算作考点。剩下 2 条是实打实的误判，一条撞上软 404，一条把暴露目录里的日志文件当成了独立问题。剔掉前 4 条，准确率 28 / 30 = 93.3%。

按类别拆开看：

| 类别 | 召回 | 说明 |
| --- | --- | --- |
| 敏感信息 | 13 / 18（72.2%） | 配置备份、数据库导出、通讯录、正文证件号与手机号；实体、零宽、JS 拼接、Base64 四种编码能还原后再判 |
| 弱配置 | 4 / 5（80.0%） | 安全响应头是否缺失、取值是否有效、版本信息是否泄露 |
| 挂马 | 1 / 5（20.0%） | eval+Base64、动态注入、Cookie 外发能认出；L2 与 L3 那种不带 eval 的注入没覆盖 |
| 篡改 | 1 / 8（12.5%） | 只有基线哈希，首轮只采基线，没有参照可对 |
| 漏洞 | 4 / 30（13.3%） | 目录索引、版本库元数据、管理入口、报错回显 |

## 二、测试方法

```powershell
# 起靶场并自检
python 靶机服务器\serve.py --port 8899

# 每关独立数据目录，两个技能顺序跑

'{"hosts":["127.0.0.1:8899","!127.0.0.1:8899/l0/"]}' | Set-Content "$env:BW_AGENT_HOME\pool.json"

Agent-Zero\build\BlueWhiteAgent.exe run skill_leak_check      http://127.0.0.1:8899/l1/

# 统计
python docs\05_测试报告\评测\eval_metrics.py .cache\eval2 --json docs\05_测试报告\评测\eval-result.json
```

数据目录须为空：发现按 `工具|归一后的目标|问题指纹` 去重，沿用旧目录会让后一轮的结论被合并掉。

## 三、真值口径

真值不按 137 条断言逐条对齐（一条断言常是另一条目的侧面），而是归并为 66 个「类别 + 载体」单元，取自 `靶机服务器\关卡设计.md` 的各关卡考点表。

| 关卡 | 真值单元 | 命中 | 召回 |
| --- | --- | --- | --- |
| L1 公开的秘密 | 13 | 9 | 69.2% |
| L2 藏与找 | 14 | 6 | 42.9% |
| L3 抗侦察 | 12 | 4 | 33.3% |
| L4 逻辑门 | 11 | 1 | 9.1% |
| L5 取证 | 10 | 1 | 10.0% |
| L6 链路 | 6 | 2 | 33.3% |
| 合计 | 66 | 23 | 34.8% |

判定规则（见 `评测/eval_metrics.py`）：

- 命中：结论的 `target` 或 `evidence` 覆盖该单元的载体路径，且类别一致（`kind` 相同，或标题命中该单元的专有特征词）。
- 有效结论：至少覆盖一个真值单元的结论。
- 误报：不覆盖任何真值单元的结论。
- 一条结论覆盖多个单元时，每个单元各计一次命中。

"线索"为 `lead_scan` 从 `robots.txt`／`sitemap.xml` 取得的路径数；"静态命中"为 `static_scan` 的行为特征条数；请求数含工具子进程发出的请求。全流程 6 轮合计 438 秒、900 次请求，另跑 6 轮敏感信息技能（各 20 秒、37 次请求），整体约 9 分 20 秒。

### 误报明细

| 关卡 | 结论 | 判定 |
| --- | --- | --- |
| L1 | `暴露内容含敏感信息(/files/README.txt)` | 真值表未收录：README 里有内网地址，属真实信息泄露 |
| L3 | `暴露日志文件(/error.log)` | 误判：站点对任意路径返回 200 的"栏目调整中"页，正文带请求路径，命中"日志文件"特征词 |
| L4 | `页面注释里留有不该公开的内容` | 真值表未收录：注释写明导出接口、附件目录与上传接口路径 |
| L4 | `配置类加固项` | 真值表未收录：缺 `Permissions-Policy` |
| L5 | `页面注释里留有不该公开的内容` | 真值表未收录：注释点明 `_notes`、`seal.png`、`download/`、`tools/restore.php` |
| L6 | `配置类加固项` | 真值表未收录：缺 `Permissions-Policy` |

### 漏检原因

| 现象 | 原因 |
| --- | --- |
| L4 召回 9.1% | 11 个考点中 6 个需要凑参数、带 `Referer`、换 `User-Agent` 才能取到；只读白名单只发 `GET`/`HEAD`/`OPTIONS`，不伪造身份 |
| L5 仅发现 1 个资产 | 首页无导航链接，线索全部写在 HTML 注释里；注释内容已能读取并报出，但不会把注释里提到的路径当作下一跳 |
| L2 `stat.js`、L3 `app.js` 未命中 | 两处用 `createElement` 加字符串拼接注入，不含 eval；现有行为特征组合不足 |
| 语义篡改（差 1 位、哈希自证、时间矛盾） | 只有基线哈希比对，需要跨页比对或外部参照值 |
| 上传、反序列化、文件包含、目录穿越 | 工具集无对应的主动验证工具；`sqli_probe` 只做布尔差分 |
| L1 `jquery.min.js`、L2/L4 `bootstrap.*` | 组件版本识别只在脚本被页面实际引用时触发，这几个文件位于目录中未被引用 |

## 五、带模型编排的对照跑

同一天、同一靶场，用同一台机器跑了一轮"人在界面上说一句话，模型自己决定调什么"的对照。指令固定为「对 http://127.0.0.1:8899/lN/ 做一次完整巡检」，逐关开新会话，审批策略用「允许只读」。

| 项 | 无编排（技能直跑） | 有编排（模型驱动） |
| --- | --- | --- |
| 覆盖关卡 | L1–L6 | L1–L5（L6 模型侧调用失败） |
| 召回（L1–L5，60 个单元） | 35.0%（21 / 60） | 35.0%（21 / 60） |
| 结论数（L1–L5） | 28 | 34 |
| 误报（L1–L5） | 5 | 10 |
| 准确率（L1–L5） | 82.1%（23 / 28） | 70.6%（24 / 34） |
| L4 召回 | 9.1%（1 / 11） | 18.2%（2 / 11） |
| 每关耗时 | 全流程 47–90 秒 | 93–186 秒 |

逐关命中：

| 关卡 | 无编排 | 有编排 |
| --- | --- | --- |
| L1 | 9 / 13 | 9 / 13 |
| L2 | 6 / 14 | 5 / 14 |
| L3 | 4 / 12 | 4 / 12 |
| L4 | 1 / 11 | 2 / 11 |
| L5 | 1 / 10 | 1 / 10 |

结论有三点。

模型没有提高召回。五关合计都是 21 个单元，L4 多拿到的那一条来自它自己补的 `http_get`＋`sensitive_scan` 组合，L2 少的一条是它在一轮里只跑了部分落点。也就是说，在这套靶场上，确定性技能链路已经覆盖了模型能想到的动作，模型多做的是**验证与转述**。

模型让误报变多。同一条注释泄露、同一处 `Permissions-Policy` 缺失，技能链路报一次，模型会在多轮里重复落库，最终 L1–L5 的结论从 28 条涨到 34 条，多出来的 5 条全是重复口径的噪声。这一点直接影响准确率：82.1% 掉到 70.6%。

L6 那一轮模型侧没跑成。三次尝试都在第一次模型调用就返回 `DS:网络: 读取响应失败 (err=12019)`，工具一次也没调用。程序按"模型不可用"收尾并如实说明，没有拿旧结论凑数——这条路径本身符合预期，但数据是缺的，所以上表把 L6 排除在对比之外。

补充一个在对照里暴露的实现问题：技能跑完后 `asset_list` 仍返回"资产底账还是空的"。技能自己爬到的页面没有写进 `asset_list` 读的那份底账，模型想顺着资产继续看时拿不到线索。

## 六、变更注入测试

在靶场副本（端口 8091）向所有页面注入 `<script src="//evil-cdn.example-malware.com/x.js"></script>` 后复跑全流程巡检：

- 页面体积 3276 → 3336 字节，注入生效。
- 第二次巡检产出 1 条结论：`[严重][挂马] 页面新增可疑外链，疑似被篡改或挂马`。
- 证据指向错误：结论写的是已有内网地址 `http://10.12.34.51:8080/`，未提及实际注入的域名。原因是可疑落点依据"廉价域名/裸 IP"规则，新注入域名不在名单内。

即：变更可发现（1/1），归因不可靠。

## 七、授权边界测试

授权池 `["127.0.0.1:8899", "!127.0.0.1:8899/l0/"]`，目标 `http://127.0.0.1:8899/l0/`：

| 项 | 结果 |
| --- | --- |
| 退出码 | 1 |
| 结论数 | 0 |
| 审计 | `{"action":"authorize","allowed":false,"detail":"路径 /l0 被授权池的排除规则拦下(主机本身在池内)"}` |

判定：通过。越界目标在发出第一个请求之前即被拦下。

## 八、边界说明

- 这一组数据来自确定性技能链路，没有大模型参与。带模型编排跑过一轮 L1，记录在 `测试报告.md` 第五节（14 次工具调用、15 步、4 条发现），两者没有可比性，别直接拿来对照。
- 只读请求不伪造身份。自定义 `Referer`、`User-Agent`、`Cookie` 一概不发，靠"换个请求头才给内容"的页面就不在覆盖范围里。
- 规则可以改（`rules\` 六个域都能编辑），但覆盖率这件事不由本作品自说自话。评测方按自己的数据集和口径来算就好，工具这边提供的是逐条能回查的证据。
